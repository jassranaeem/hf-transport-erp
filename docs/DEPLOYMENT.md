# Deployment

The app is one Node process that serves the built React SPA + the API + the
socket.io real-time layer. It needs **PostgreSQL**. Redis is optional (in-memory
fallback for a single instance).

- **HTTPS is required in production** - session tokens ride in the browser.
  Every option below terminates TLS for you or via Nginx.
- Database migrations run automatically on boot (`MIGRATE_ON_BOOT=true`).
- First boot creates the Super Admin (`SUPER_ADMIN_EMAIL`); if you didn't set
  `SUPER_ADMIN_PASSWORD`, the generated one is printed to the logs **once**.

---

## Option A - Render + Neon  (free, recommended to start)

**1. Database - Neon (free, no time limit)**

1. https://neon.tech -> new project -> copy the **pooled** connection string
   (looks like `postgresql://user:pass@ep-xxx-pooler.../neondb?sslmode=require`).

**2. App - Render (free web service)**

1. Push this repo to GitHub.
2. Render -> **New -> Blueprint** -> pick the repo. It reads [`render.yaml`](../render.yaml).
3. Set the `sync:false` env vars in the dashboard:
   - `DATABASE_URL` = the Neon pooled string
   - `SUPER_ADMIN_PASSWORD` = a strong password (you can change it in-app later)
   - `APP_URL` = `https://<your-service>.onrender.com`
   - `GEMINI_API_KEY`, `GOOGLE_CLIENT_ID` = optional
   - `JWT_SECRET` is auto-generated by Render.
4. Deploy. Open the URL, sign in as `jassranaeem@gmail.com`.

Free-tier caveats: the web service sleeps after ~15 min idle (first request
after that takes ~30 s), cron jobs don't run while asleep, and the local
`./uploads` folder is wiped on redeploy/restart (fine unless you rely on the
DMS file store).

To enable **Sign in with Google**: create an OAuth 2.0 **Web** client at
<https://console.cloud.google.com/apis/credentials>, add
`https://<your-service>.onrender.com` to *Authorized JavaScript origins*, and
set `GOOGLE_CLIENT_ID`.

## Option B - Docker on your own server

```bash
cp .env.production.example .env.production      # fill JWT_SECRET etc.
export POSTGRES_PASSWORD='a-strong-db-password'
docker compose -f docker-compose.prod.yml up -d --build
```

This runs app + Postgres + Redis with healthchecks. The app binds to
`127.0.0.1:3000`; put Nginx (see [`nginx.conf`](../nginx.conf)) or Caddy in
front for TLS:

```bash
sudo apt install nginx certbot python3-certbot-nginx
sudo cp nginx.conf /etc/nginx/nginx.conf   # edit server_name first
sudo certbot --nginx -d erp.yourdomain.com
```

Backups: `docker compose -f docker-compose.prod.yml exec db pg_dump -U erp hf_transport_erp | gzip > backup-$(date +%F).sql.gz`

## Option C - Bare VPS with PM2

```bash
npm ci && npm run build
cp .env.production.example .env.production      # fill it in (incl. DATABASE_URL)
npm i -g pm2
pm2 start ecosystem.config.js --env production
pm2 save && pm2 startup
```

Nginx in front for TLS, same as Option B. Single instance only (see the note in
`ecosystem.config.js`).

## Option D - Google Cloud Run

```bash
gcloud run deploy hf-transport-erp \
  --source . --region=us-central1 --allow-unauthenticated \
  --set-env-vars NODE_ENV=production,TRUST_PROXY=1,MIGRATE_ON_BOOT=true \
  --set-secrets DATABASE_URL=DATABASE_URL:latest,JWT_SECRET=JWT_SECRET:latest,SUPER_ADMIN_PASSWORD=SUPER_ADMIN_PASSWORD:latest
```

Use Cloud SQL (Postgres) or Neon. Set `--min-instances=1` if you want cron and
sockets to stay alive.

## Environment variables

See [`.env.production.example`](../.env.production.example). The essentials:

| var | required | note |
|-----|----------|------|
| `DATABASE_URL` | yes | managed Postgres; include `?sslmode=require` |
| `DATABASE_SSL` | if TLS DB | `true` |
| `JWT_SECRET` | yes | >= 32 random chars; the server refuses to start in prod without it |
| `NODE_ENV` | yes | `production` |
| `TRUST_PROXY` | behind a proxy | `1` |
| `APP_URL` | recommended | your public URL |
| `SUPER_ADMIN_EMAIL` | no | default `jassranaeem@gmail.com` |
| `SUPER_ADMIN_PASSWORD` | recommended | else printed to logs once |
| `GOOGLE_CLIENT_ID` | no | enables Google sign-in |
| `GEMINI_API_KEY` | no | AI features |
| `REDIS_URL` | to scale | needed before running >1 instance |

## Health checks

- `GET /healthz` - liveness, no DB, returns `ok`.
- `GET /api/health` - returns JSON with service info.

## Migrations

- Generated into `./drizzle` by `npm run db:generate` (commit the folder).
- Applied automatically on boot, or manually: `npm run db:migrate`.
- After changing `src/db/schema.ts`: `npm run db:generate`, review the SQL,
  commit, deploy.
